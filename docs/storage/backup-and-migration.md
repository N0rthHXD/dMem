# dMeM 备份、恢复与迁移

## 1. 备份类型

### 1.1 权威备份

包含：

- SQLite 一致性快照。
- 原始内容和附件。
- 配置版本和 schema 版本。
- 必要的删除清单和 schema 版本。

### 1.2 逻辑导出

当前由 `internal/portability` Go library 实现，不是 `dmemd` 子命令或 HTTP API。

包含指定空间中的：

- 原始事件或可选摘要。
- 记忆和版本。
- 证据和关系。
- 生命周期状态。
- 来源和处理版本。

### 1.3 派生索引快照

可选。索引可以在恢复后重建，不属于最小可靠备份。

## 2. 一致性边界

不能通过随意复制正在写入的数据库和附件目录宣称获得一致备份。备份操作必须：

1. 获得 SQLite 一致性快照。
2. 记录附件清单和校验值。
3. 记录备份开始和完成时的数据库版本。
4. 记录未完成任务和处理版本。
5. 生成完整性清单。

## 3. 恢复流程

```text
进入维护模式
  → 校验备份清单
  → 恢复 SQLite 和附件
  → 检查 schema 兼容性
  → 恢复删除清单
  → 处理未完成任务
  → 重建或校验派生索引
  → 完整性检查
  → 恢复服务
```

恢复后不能盲目重放所有 `running` 任务。必须先检查目标对象、幂等记录和外部副作用。

## 4. 恢复验证

定期验证：

- SQLite 可打开并通过完整性检查。
- 附件校验值一致。
- 记忆当前投影指向存在版本。
- 证据引用存在。
- 任务状态可解析。
- 索引可以重建。

只生成备份而不测试恢复不算完整备份策略。

## 5. 未发布开发阶段 Schema 策略

项目明确完成并发布前，所有开发阶段只支持新数据库初始化，不实现 SQLite schema migration：

- 备份记录精确 schema 版本。
- 恢复时要求 daemon 支持该 schema 版本。
- schema 版本不匹配时停止恢复后的普通启动，不自动修改数据库。
- Schema 变化时直接重新初始化开发数据库，不提供旧数据升级、导入适配或双版本读取。
- 阶段编号不触发迁移义务；只有项目负责人明确声明项目开发完成并发布后才重新评估。

## 6. 处理和模型版本变化

处理规则、模型或嵌入变化不要求 SQLite schema migration：

- 处理规则变化增加 `processing_version`。
- 嵌入变化创建新的索引版本。
- 旧权威记忆继续存在。
- 重处理创建新版本或新派生数据，不覆盖原始事件。
- 混合版本查询必须返回处理和索引新鲜度。

## 7. 导入

导入流程：

```text
读取清单
  → 格式和版本校验
  → 完整性校验
  → 映射目标空间
  → 标记 imported 来源
  → 幂等检查
  → 写入权威数据
  → 创建索引任务
```

导入数据不自动获得比本地数据更高的可信度。冲突内容进入正常记忆演进流程。当前入口是 `portability.NewImporter` 的 dry-run/import/status/cancel 方法；`make export-import-drill` 是可执行验收入口，不是用户迁移 CLI。

## 8. 导出格式要求

便携导出至少包含：

```text
format_version
export_id
created_at
source_identity
spaces
memories
revisions
evidence
relations
lifecycle_state
processing_versions
integrity_manifest
```

嵌入向量只在模型身份和维度完全记录时可选导出，否则恢复后重建。
