# dMeM 架构设计

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 系统名称 | dMeM |
| 运行形态 | Linux 系统用户拥有的本地常驻 daemon |
| 基础实现 | Go + SQLite 嵌入式数据库 |
| 数据边界 | 默认仅服务当前 Linux 用户，不默认开放网络访问 |
| Agent 信任模型 | 第一阶段同一系统用户下的 Agent 全部可信 |
| 文档状态 | 初始架构设计 |

本文档定义 dMeM 的模块边界、核心对象、数据流、运行约束和演进方向。文档描述实现所需的架构决策，但不绑定具体的外部技术框架、模型服务或索引产品。

## 2. 目标与非目标

### 2.1 目标

- 接收外部 Agent、应用和采集器产生的事件、消息、对话和工具调用。
- 可靠保存原始数据，使原始内容可以重放、重新提取和审计。
- 将原始数据异步转换为版本化、可追溯的结构化记忆。
- 提供关键词、语义、实体和关系等多种检索能力。
- 在作用域、时间、生命周期和上下文预算约束下返回可直接使用的记忆结果。
- 通过单一 Linux 用户下的常驻进程提供统一服务，避免每个 Agent 单独维护记忆库。
- 在外部模型不可用、派生索引损坏或 daemon 重启时保持可恢复性。
- 使权威数据和派生索引职责分离，支持索引重建、数据迁移和备份恢复。

### 2.2 非目标

第一阶段不包含以下能力：

- 自动修改基础模型参数或训练模型适配器。
- 跨模型迁移运行时激活状态或 KV 状态。
- 让模型自主永久删除原始事实。
- 默认提供跨用户、跨主机或云端共享。
- 默认引入独立的图数据库或其他外部基础设施。
- 执行未经验证的 Skill 或工作流。
- 让存储实现决定记忆提取、冲突处理或检索排序规则。

              ▼

      ├── 格式转换
      ├── 基础校验
      ├── 幂等标识
      └── 元数据补充
              │
              ▼
         原始记忆层
      ├── 原始事件
      ├── 原始内容
      ├── 附件引用
      └── 来源上下文
              │
              ▼
       记忆形成与演进层
      ├── 记忆选择
      ├── 信息提取
      ├── 实体与时间识别

      ├── 合并与修订
      ├── 版本与状态转换
      └── 证据关联
              │
              ▼
        权威记忆模型
      ├── 原子记忆

      ├── 当前有效视图
      ├── 历史版本
      └── 来源证据
              │
              ▼
        记忆检索与装配层

横向能力：

```text
记忆空间与作用域
任务调度与恢复
生命周期与反馈
数据存储与索引
运行治理与可观测性
导入导出与迁移
质量评估
```

## 4. 部署与进程模型

### 4.1 单一用户 daemon

dMeM 以一个 Go 进程运行，由一个 Linux 系统用户拥有。默认情况下：

- 数据目录属于该用户。
- 服务端点位于该用户的运行时目录。
- 不监听对外网络地址。
- 同一用户只允许一个有效 daemon 实例使用同一数据目录。
- daemon 重启后从 SQLite 恢复任务和状态。

“同一用户下 Agent 全部可信”是第一阶段的业务假设，不代表调用方身份不存在。系统仍记录 `agent_id`、`application_id`、`project_id` 和 `session_id`，用于作用域、来源、配额、诊断和未来隔离。

### 4.2 Go 进程内部边界

建议按职责划分 Go 内部包或模块，包之间通过领域命令、查询和接口交互：

```text
cmd/daemon                 进程启动、信号、配置和生命周期
interface                  本地服务端点、协议、版本和请求限制
adapter                    外部输入适配和统一事件转换
domain                     记忆对象、状态、版本和业务规则
ingest                     原始事件接收和幂等处理
extract                    记忆选择、提取和候选生成
evolution                  去重、冲突、合并、修订和反馈
retrieve                   查询、召回、融合和排序
context                    上下文预算和结果装配
jobs                       任务状态、队列、重试和恢复
lifecycle                  过期、归档、冻结、清理和重建
repository                 权威数据访问接口
index                      派生索引接口和重建
storage                    SQLite 连接、事务、schema 初始化和备份
governance                资源、隐私、健康和审计
```

以上是职责边界，不要求一开始严格采用相同目录结构。业务规则应位于 `domain`、`extract`、`evolution`、`retrieve` 和 `lifecycle`，不能下沉到 SQLite 读写代码。

### 4.3 外部处理能力

LLM、嵌入、重排和其他外部处理能力均属于可替换的处理端口。它们不是 dMeM 的权威数据源，也不能改变以下不变量：

- 原始事件先持久化，再进行异步处理。
- 处理失败不会删除原始事件。
- 每次处理记录处理配置、模型标识和结果状态。
- 外部调用的数据外发策略必须可配置并可审计。

## 5. 分层职责

### 5.1 接口与接入服务层

负责外部调用进入 daemon 的边界：

- 暴露写入、查询、修改、删除、任务状态和管理操作。
- 验证请求结构、大小、超时和版本。
- 记录调用方和操作标识。
- 将请求转换为内部命令或查询。
- 返回同步完成、异步已接收、处理中、降级和失败状态。
- 不直接决定记忆是否值得保存。

第一阶段允许所有本地可信 Agent 共享完整能力，但破坏性操作仍必须记录调用方和作用域。

### 5.2 数据适配层

负责把外部数据转换为统一的内部原始事件：

- 对话消息。
- Agent 输出。
- 工具调用和工具结果。
- 文件或文档事件。
- 任务状态变化。
- 其他采集器事件。

统一事件至少包含：

```text
event_id
operation_id
source_type
source_name
agent_id
application_id
project_id
session_id
occurred_at
received_at
content
content_type
metadata
```

适配层只负责格式转换、基础校验和元数据补充，不负责记忆提取和长期保存决策。

### 5.3 原始记忆层

原始记忆层是原始事实来源，负责：

- 保存原始事件和原始内容。
- 保存发生时间、接收时间和来源信息。
- 保存原始上下文、角色和会话关联。
- 支持幂等写入、追加、查询和重放。
- 为后续处理提供稳定输入。
- 在结构化记忆被修订或删除后仍按策略保留来源依据。

原始事件不因提取失败而丢失，也不因为生成了结构化记忆而被立即替换。

### 5.4 记忆形成与演进层

由以下逻辑阶段组成：

```text
记忆选择
   ↓
信息提取
   ↓
实体、关系和时间识别
   ↓
候选记忆生成
   ↓
去重与冲突检测
   ↓
合并、修订或建立新记忆
   ↓
版本、状态和证据更新
```

自动处理可以提出新增、补充、替代和冲突建议，但默认不物理删除历史事实。模型生成的结论应通过候选状态、来源证据和版本化变更进入权威记忆。

### 5.5 记忆检索与装配层

检索由两部分组成：

```text
候选检索：找到可能相关的记忆
上下文装配：决定最终返回哪些内容以及如何组织
```

候选检索支持：

- 关键词检索。
- 语义检索。
- 实体检索。
- 关系检索。
- 时间检索。
- 结构化过滤。

上下文装配负责：

- 从权威记忆确认当前版本和状态。
- 排除过期、撤回和不可用版本。
- 识别冲突和不确定性。
- 去重和控制多样性。
- 应用条数、字符数或 Token 预算。
- 附带来源、版本和选择解释。

### 5.6 数据存储实现层

SQLite 是第一阶段的嵌入式权威数据存储和任务状态存储。存储层负责：

- 建立和维护 SQLite 连接。
- 执行事务和查询。
- 初始化新数据库 schema 并校验 schema 版本。
- 保存权威记录和派生索引元数据。
- 提供备份、恢复和完整性检查。

存储层不负责：

- 判断记忆是否重要。
- 选择冲突胜者。
- 决定检索排序。
- 解释 Agent 意图。
- 决定生命周期业务规则。

## 6. 权威数据与派生数据

### 6.1 权威数据

SQLite 中以下内容是权威数据：

- 原始事件。
- 原始内容元数据。
- 记忆逻辑对象。
- 记忆版本和当前投影。
- 证据关联。
- 记忆关系的业务状态。
- 处理任务和任务状态。
- 反馈事件。
- 审计事件。
- 作用域和生命周期状态。

### 6.2 派生数据

以下内容均为可重建数据：

- 关键词索引。
- 向量和嵌入索引。
- 实体索引。
- 关系查询加速索引。
- 高层摘要。
- 检索缓存。
- 上下文装配缓存。
- 统计聚合。

派生数据损坏时，系统应能够从 SQLite 权威记录和原始事件重建。派生索引不可用不应阻止原始数据读取、结构化记忆管理和降级查询。

## 7. SQLite 数据组织

以下是逻辑表分组，不是固定 SQL 方言或最终字段定义。

### 7.1 原始数据组

```text
raw_events
raw_contents
attachments
event_metadata
```

`raw_events` 保存事件身份、来源、作用域和时间；大内容可以通过 `raw_contents` 或附件引用保存，避免所有内容都堆积在事件主表中。

### 7.2 记忆组

```text
memories
memory_revisions
memory_projections
memory_evidence
memory_relations
memory_spaces
```

建议：

- `memories` 表示稳定的逻辑记忆身份。
- `memory_revisions` 保存不可变版本。
- `memory_projections` 保存当前检索视图，必要时可重建。
- `memory_evidence` 连接版本和原始事件或内容范围。
- `memory_relations` 保存支持、冲突、替代、派生和关联关系。
- `memory_spaces` 保存项目、Agent、任务和会话等空间。

### 7.3 任务与反馈组

```text
jobs
job_attempts
job_dependencies
feedback_events
audit_events
```

任务表必须保存：

- 任务身份和幂等键。
- 任务类型和目标对象。
- 当前状态。
- 重试次数和下一次执行时间。
- 处理配置和模型版本。
- 错误类别和错误信息摘要。
- 创建、开始、结束和过期时间。

### 7.4 索引组

```text
keyword_index_metadata
embedding_index_metadata
entity_index
relation_index
index_builds
```

SQLite 可提供基础关键词索引和结构化过滤。语义索引可以作为 SQLite 内的可选派生数据，也可以通过独立实现提供，但其记录必须能回指 `memory_id` 和 `revision_id`。

无论索引在哪里，索引都不能成为当前记忆内容的唯一来源。

## 8. 核心领域对象

### 8.1 原始事件

原始事件表示“外部系统报告发生了什么”。主要属性：

```text
event_id
operation_id
source_type
source_name
caller_id
agent_id
application_id
project_id
session_id
occurred_at
received_at
content_ref
metadata
retention_policy
```

事件 ID 和操作 ID 支持去重、重试和审计。`occurred_at` 与 `received_at` 必须分开保存。

### 8.2 记忆

记忆表示稳定的逻辑身份，而不是某一版具体文本：

```text
memory_id
memory_type
space_id
created_at
current_revision_id
current_state
retention_policy
sensitivity
```

### 8.3 记忆版本

记忆版本保存某一时刻的完整内容和状态：

```text
revision_id
memory_id
parent_revision_id
content
content_type
valid_from
valid_until
status
confidence
created_at
created_by
processing_version
model_identity
```

版本应记录来源和处理上下文，不应原地改变已经发布的历史版本。

### 8.4 证据关联

证据关联至少包含：

```text
revision_id
event_id
content_ref
evidence_range
evidence_type
extraction_method
created_at
```

`evidence_type` 用于区分直接陈述、工具结果、模型推断、人工确认和外部导入。

### 8.5 记忆关系

完整架构后续支持以下关系：

```text
supports
contradicts
supersedes
derived_from
related_to
belongs_to
mentions
```

关系本身也应有版本、状态和来源。关系索引是派生查询能力，但关系的业务状态属于权威数据。

## 9. 记忆空间与作用域

建议支持以下空间类型：

```text
user
agent
application
project
task
session
imported
shared-local
```

空间用于组织和查询过滤。第一阶段同一系统用户下的 Agent 共享完整访问能力，但仍应显式传递和保存空间上下文：

```text
查询
  → 确定当前项目和任务
  → 确定可查询空间
  → 在空间内召回
  → 按空间优先级合并
```

默认查询不应跨所有项目和会话盲目搜索。调用方应显式提供空间，或者由接口层根据当前 Agent 上下文确定默认空间。

## 10. 生命周期

### 10.1 内容状态

```text
candidate    候选，尚未确认
active       当前可参与常规检索
contested    存在冲突或待处理
superseded   被新版本替代
archived     归档，默认不参与常规检索
expired      超出有效期
retracted    被明确撤回
deleted      从当前服务中删除
```

### 10.2 正交标记

```text
frozen       不允许自动修改
pending_review 需要人工查看
sensitive    受特殊保留和输出规则约束
```

### 10.3 状态原则

- 被替代不等于物理删除。
- 归档不等于不可恢复。
- 过期不等于已经清除所有副本。
- 删除必须说明原始内容、索引、缓存、任务、日志和备份的清除范围。
- 恢复历史版本应创建新版本，不修改历史链。

## 11. 写入数据流

```text
外部数据
  → 接口校验
  → 数据适配
  → 分配 operation_id 和 event_id
  → 幂等检查
  → 原始事件事务持久化
  → 返回已接收
  → 创建记忆处理任务
  → 记忆选择
  → 信息提取
  → 实体、关系和时间识别
  → 生成候选记忆
  → 去重与冲突检测
  → 创建或修订记忆版本
  → 绑定来源证据
  → 更新当前投影
  → 创建索引更新任务
  → 更新派生索引
```

写入接口的确认语义：

| 返回状态 | 含义 |
| --- | --- |
| accepted | 原始事件已可靠保存，后续处理未必完成 |
| processed | 记忆提取和权威记忆更新已完成 |
| indexed | 相关派生索引已更新 |
| deferred | 已保存但等待资源或外部处理能力 |
| rejected | 数据未被接受，调用方可根据错误修正 |
| failed | 处理失败，原始事件是否保存必须明确返回 |

原始事件保存与记忆提取不能使用同一个不可恢复的外部模型调用作为提交条件。

## 12. 记忆演进数据流

```text
新事实或用户反馈
  → 查找相关当前记忆
  → 读取历史版本和证据
  → 判断补充、冲突、替代或无关
  → 创建新记忆版本
  → 标记旧版本状态
  → 更新当前投影
  → 更新关系和证据
  → 重建相关派生索引
```

默认处理规则：

- 新信息可以新增记忆。
- 新信息可以补充已有记忆并创建新版本。
- 新信息可以使旧记忆进入 `superseded` 或 `contested`。
- 新信息不直接清除原始事件。
- 模型无法确定冲突时保留冲突并标记，不强行选出唯一事实。

## 13. 查询数据流

```text
查询请求
  → 确定空间、Agent、项目、任务和时间范围
  → 查询理解
  → 生成多路检索请求
  → 关键词召回
  → 语义召回
  → 实体与关系召回
  → 时间召回
  → 合并候选集合
  → 统一排序
  → 读取权威当前版本
  → 排除无效状态
  → 处理时间和冲突
  → 去重和多样性控制
  → 应用上下文预算
  → 返回内容、来源和解释
```

### 13.1 多路召回

候选集合应是各路检索结果的并集：

```text
关键词候选
    ∪ 语义候选
    ∪ 实体候选
    ∪ 关系候选
    ∪ 时间候选
```

关键词和实体信号不能只给已经进入语义候选的记录加分，否则精确文件名、命令、错误码和标识符可能无法被召回。

### 13.2 排序信号

排序可以综合：

```text
语义相关性
关键词相关性
实体匹配
关系匹配
时间匹配
空间匹配
来源可靠性
记忆状态
访问频率
新鲜度
冲突惩罚
内容成本
```

权重属于检索业务规则，不属于 SQLite 或索引实现。

## 14. 上下文装配

检索结果不是简单的前 N 条文本。装配过程为：

```text
候选记忆
  → 权威版本确认
  → 状态和作用域过滤
  → 冲突分组
  → 去重
  → 高层摘要优先
  → 原子事实补充
  → 按预算截断
  → 添加来源和解释
```

建议结果包含：

```text
memory_id
revision_id
content
memory_type
space
status
valid_time
relevance
evidence_refs
conflict_refs
selection_reason
```

预算至少包括：

- 最大记忆数量。
- 最大总字符或 Token 数。
- 单条记忆最大长度。
- 最大检索时间。
- 是否允许返回原始证据。
- 不同记忆类型的优先级。

## 15. 任务调度与恢复

### 15.1 任务类型

```text
extract_memory
evolve_memory
build_summary
update_keyword_index
update_embedding_index
update_entity_index
rebuild_index
expire_memory
purge_data
export_data
import_data
```

### 15.2 任务原则

- 任务状态持久化在 SQLite。
- 任务必须有稳定身份和幂等键。
- 任务分为可重试、不可重试和等待依赖三类。
- 重试使用有上限的退避策略。
- daemon 重启后恢复 `running` 状态的中断任务。
- 任务失败不能回滚已经可靠保存的原始事件。
- 派生索引任务失败可以通过重建恢复。
- 外部模型长时间不可用时不应形成无限增长的无界队列。

### 15.3 队列和资源

必须设置：

- 总任务队列上限。
- 单类任务并发上限。
- 单 Agent 或空间的资源上限。
- 单请求内容大小上限。
- 单任务处理时间上限。
- 临时文件和附件空间上限。
- 磁盘低水位和只读保护阈值。

过载时必须明确选择阻塞、延迟、拒绝或降级，不能静默丢弃。

## 16. SQLite 事务与一致性

### 16.1 原始事件提交

以下操作应在同一个 SQLite 事务内完成：

```text
写入原始事件
写入原始内容引用
写入幂等记录
创建初始处理任务
```

事务提交后才能向调用方返回 `accepted`。

### 16.2 记忆版本提交

以下操作应在同一个事务内完成：

```text
创建记忆版本
写入证据关联
写入版本关系
更新当前投影
写入审计事件
创建派生索引任务
```

索引实际更新可以在事务后异步执行，但权威数据和索引任务必须同时提交。

### 16.3 并发更新

修改记忆时使用版本条件：

```text
update(memory_id, expected_revision_id, patch)
```

当当前版本已经改变时返回冲突，由业务层重新读取和合并，不能静默覆盖其他修改。

## 17. 幂等、重放与故障恢复

### 17.1 幂等边界

以下操作必须支持幂等：

- 原始事件写入。
- 任务创建。
- 记忆版本创建。
- 索引更新任务。
- 导入和导出。
- 删除和清理任务。

幂等键应由调用方或 daemon 生成，并在足够长的保留期内可查询。

### 17.2 恢复流程

```text
daemon 启动
  → 检查单实例
  → 检查 SQLite 完整性
  → 恢复未完成任务
  → 标记中断任务为可重试或失败
  → 检查派生索引版本
  → 进入可用或降级状态
```

权威数据损坏和派生索引损坏必须返回不同的健康状态和恢复建议。

## 18. 删除、保留与隐私

删除操作需要定义范围：

```text
逻辑记忆
记忆版本
原始事件
原始内容
证据
关系
关键词索引
向量索引
实体索引
缓存
等待中的任务
审计记录
导出包
备份
```

建议区分：

- 立即从正常检索中排除。
- 后台清除派生索引和缓存。
- 清除原始内容和附件。
- 按审计策略保留最小操作元数据。
- 在后续备份周期中完成备份清理。

默认不上传遥测，不记录原始内容到普通日志。外部模型调用必须遵循数据外发策略并记录处理来源。

## 19. 本地 daemon 运行治理

### 19.1 端点

默认只提供本地端点，并保证：

- 端点由当前用户拥有。
- 端点路径不可被其他用户写入。
- stale endpoint 不会导致客户端连接错误 daemon。
- 请求有最大帧大小、读取超时和执行超时。
- 不因 loopback 或本地网络位置将服务视为远程安全端点。

如未来支持网络访问，应作为独立部署模式，重新定义认证、授权、加密、暴露范围和审计要求。

### 19.2 健康状态

至少提供：

```text
process_alive
accepting_writes
query_available
storage_healthy
index_freshness
job_queue_depth
provider_available
disk_pressure
schema_compatibility
```

“daemon 正在运行”不等于“所有记忆能力都可用”。响应应携带必要的降级信息，不能把陈旧或部分结果伪装成完整结果。

### 19.3 资源预算

资源治理范围：

- CPU。
- 进程内存。
- SQLite 文件空间。
- 派生索引空间。
- 临时工作空间。
- 队列长度。
- 同时处理数。
- 单 Agent 或空间的使用量。
- 外部模型调用量。

应为恢复、压缩、删除和关闭保留最低可用空间，避免磁盘耗尽时无法完成数据维护。

## 20. 备份、兼容性与重建

### 20.1 备份

备份至少需要包含：

- SQLite 权威数据库。
- 大对象和附件。
- 配置和 schema 版本。
- 处理规则版本。
- 可选派生索引快照。

派生索引可以不备份，恢复后重建；权威数据库和原始内容必须作为一致性快照备份。

备份策略必须包含恢复验证，而不只是生成备份文件。

### 20.2 第一阶段 Schema 兼容性

第一阶段不实现 SQLite schema migration：

- 新数据库通过版本化初始化 SQL 一次性创建完整 schema。
- 数据库保存单一 schema 版本。
- daemon 打开已有数据库时要求版本完全匹配。
- 版本不匹配时拒绝普通启动并返回 `incompatible_version`。
- 不使用 ORM AutoMigrate，也不在启动时自动修改已有表。
- 开发阶段发生不兼容变更时，使用新数据库重新初始化；需要保留的数据通过明确导出和导入处理。

正式 schema migration 属于后续阶段，届时单独设计和记录。接口版本、数据模型版本、处理版本和索引版本仍分开管理。

### 20.3 索引重建

```text
读取权威记忆版本
  → 按当前索引配置生成候选数据
  → 构建新索引
  → 校验记录数量和版本
  → 切换索引版本
  → 清理旧索引
```

构建失败时保留旧索引或进入无索引降级状态，不能覆盖权威数据。

## 22. 错误和降级语义

调用方应能区分：

```text
invalid_request
duplicate_request
retryable_overload
dependency_unavailable
processing_failed
authorization_failed
revision_conflict
storage_unavailable
index_degraded
incompatible_version
resource_exhausted
```

典型降级：

| 故障 | 行为 |
| --- | --- |
| 外部模型不可用 | 原始事件照常保存，提取任务等待或重试 |
| 向量索引不可用 | 使用关键词和结构化过滤，标记降级 |
| 关键词索引不可用 | 使用语义或基础结构化查询，标记降级 |
| 派生索引损坏 | 权威数据继续可读，后台重建 |
| 磁盘接近耗尽 | 停止非关键任务，限制大对象写入，保留删除能力 |
| SQLite 不可写 | 拒绝需要持久化的写入，不返回虚假的成功 |
| daemon 重启 | 恢复任务，重建不一致的派生数据 |

安全、作用域、删除和审计不应在降级模式下被静默绕过。

## 23. 可观测性

每次操作应具备关联标识：

```text
operation_id
request_id
job_id
event_id
memory_id
revision_id
```

记录以下指标但默认不记录原始内容：

- 写入数量和失败率。
- 原始事件到记忆形成的延迟。
- 查询延迟和分位数。
- 各召回通道候选数量。
- 上下文预算使用率。
- 任务队列深度和最老任务年龄。
- 重试次数和失败类别。
- 索引新鲜度。
- SQLite 空间、索引空间和临时空间。
- 外部处理调用延迟和失败率。
- 记忆修订、冲突和删除数量。

日志必须避免泄露：

- 原始对话。
- 工具输出。
- 外部模型密钥。
- 完整记忆内容。
- 不必要的路径和身份信息。

## 24. 质量评估

评估范围：

```text
接入：格式失败、丢失、重复
提取：准确、遗漏、幻觉、证据覆盖
演进：冲突识别、版本正确、错误覆盖

```

测试数据应覆盖：

- 单事实查询。
- 偏好和约束查询。
- 时间和当前状态查询。
- 跨会话查询。
- 多跳关系查询。
- 冲突事实查询。
- 过期和撤回记忆查询。
- 错误记忆纠正。
- 不相关或不可回答问题。

## 25. 分阶段实现

### 阶段一：可靠的本地记忆基础

- Go daemon 生命周期。
- SQLite schema 初始化、版本校验和事务。
- 本地服务端点。
- 统一原始事件模型。
- 原始事件可靠写入和幂等。
- 记忆、版本、状态和证据模型。
- 基础异步任务状态。
- 结构化和关键词检索。
- 查看、修订、归档和删除。
- 健康状态、日志和基本指标。
- 第一阶段完整边界以 `phase-1-scope.md` 为准。

### 阶段二：语义检索与自动处理

- 语义索引。
- 多路候选并集。
- 自动处理 provider。
- 候选提取和审核。
- 备份和恢复验证。
- 外部处理不可用时的明确降级。

### 阶段三：记忆演进与反馈

- 实体辅助检索。
- 关系和冲突模型。
- 场景聚合和长期画像。
- 使用反馈驱动排序。
- 导入导出和记忆迁移。

### 阶段四：高级记忆能力

- 文档和代码知识资产。
- 多模态内容。
- 可验证的 Skill 候选。
- 可选图关系增强。
- 特定模型运行时的缓存适配。
- 更细的 Agent 隔离和授权。

以下能力不作为阶段一基础依赖：参数记忆、自动训练、跨模型激活迁移和自动发布共享。

## 26. 核心架构决策摘要

1. **原始事件是事实依据，结构化记忆是业务权威。**
2. **记忆是带版本、状态、时间和证据的对象。**
3. **默认追加和版本化修订，不让模型直接破坏历史。**
4. **SQLite 保存权威数据和任务状态，派生索引可以重建。**
5. **原始数据接收与记忆提取异步解耦。**
6. **L0、原子、场景和画像是可选的渐进式视图，不是强制物理层级。**
7. **关键词、语义、实体和关系检索使用候选并集后统一排序。**
8. **时间是独立属性，发生时间和处理时间不能混淆。**
9. **上下文装配独立于候选检索，并受明确预算约束。**
10. **本地优先、默认无外发、默认不开放网络访问。**
11. **第一阶段 Agent 全部可信，但保留逻辑身份、作用域和审计。**
12. **Go 业务模块依赖抽象存储接口，SQLite 实现不决定业务规则。**
13. **模型、嵌入和重排能力通过处理端口接入，外部依赖失败不能导致原始事实丢失。**
14. **删除必须定义从权威数据到缓存、任务、日志和备份的完整范围。**
15. **运行健康、数据健康、索引健康和处理依赖健康必须分开表达。**

## 27. 最终数据流

```text
外部 Agent / 应用 / 采集器
  → 接口服务
  → 数据适配
  → 原始事件事务保存
  → 异步任务调度
  → 记忆选择与信息提取
  → 候选记忆
  → 去重、冲突、合并和修订
  → 版本化权威记忆
  → 来源证据和生命周期状态
  → 派生关键词、语义、实体和关系索引
  → 查询理解和多路候选召回
  → 权威版本确认
  → 时间、冲突和作用域处理
  → 上下文预算与装配
  → 返回记忆、来源、解释和处理状态
```

dMeM 的核心可以概括为：

> **数据适配负责接入，原始记忆负责保存事实，记忆形成与演进负责产生版本化权威记忆，检索与装配负责在约束下使用记忆，SQLite 负责嵌入式持久化，Go daemon 负责把这些能力组织成一个可恢复、可观测、可长期运行的本地服务。**
