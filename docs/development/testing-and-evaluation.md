# dMeM 测试与质量评估

## 1. 测试层次

```text
领域规则测试
SQLite repository 测试
任务处理和恢复测试
接口契约测试
daemon 生命周期测试
端到端数据流测试
性能和资源测试
故障注入测试
记忆质量评估
```

## 2. 领域规则测试

验证：

- 记忆版本不可变。
- 当前投影只指向有效版本。
- 版本条件更新检测冲突。
- 状态转换符合生命周期规则。
- 冻结记忆不能被自动替代。
- 删除、撤回、过期和归档的检索行为不同。
- 证据和关系不形成非法引用。

## 3. SQLite 测试

验证：

- 原始事件和任务在同一事务提交。
- 记忆版本、证据、投影和索引任务原子提交。
- 幂等键防止重复写入。
- 外键、唯一约束和必要索引有效。
- 初始化 SQL 能创建完整 schema，且 schema 版本正确。
- 不兼容 schema 被拒绝，数据库内容不被自动修改。
- 数据库重新打开后数据和任务状态一致。

## 4. 任务测试

场景：

- daemon 在任务运行时崩溃。
- 外部模型超时或限流。
- 模型返回非法结构。
- 索引更新部分成功。
- 同一任务重复投递。
- 队列达到上限。
- 任务取消和过期。
- 重试达到最大次数。

验证原始事件始终保留，重复执行不产生重复权威版本。

## 5. 接口契约测试

- API 版本协商。
- 未知字段行为。
- 请求大小和超时限制。
- `accepted`、`processed` 和 `indexed` 语义。
- 错误类别和重试标志。
- 分页、排序和预算截断。
- 并发修订返回 `revision_conflict`。
- 降级响应包含索引和新鲜度信息。

## 6. daemon 生命周期测试

- 第二个实例不能写同一数据目录。
- stale endpoint 可以安全恢复。
- 启动完整性检查失败时不返回 ready。
- 优雅关闭停止接收新任务并保存中断状态。
- 强制退出后下一次启动能恢复任务。
- 磁盘低水位进入受限模式。
- 维护模式拒绝普通写入。

## 7. 端到端场景

```text
事件写入 → 原始数据查询 → 记忆提取 → 版本提交 → 索引 → 查询
新事实 → 冲突检测 → contested → 人工确认 → active
记忆修订 → 历史版本查询 → 恢复为新版本
删除空间 → 默认检索排除 → 派生清理 → 备份清理待处理
索引删除 → 降级查询 → 重建 → 正常查询
```

## 8. 故障注入

- SQLite 写入前、事务中和提交后终止进程。
- 附件写入失败。
- 外部处理连接失败、超时和非法响应。
- 索引文件损坏。
- 数据库进入只读。
- 磁盘空间不足。
- 备份中断和恢复中断。
- 数据库 schema 版本不兼容。

每种故障必须验证确认语义、恢复行为和健康状态。

## 9. 性能与资源

测量：

- 原始事件接收延迟。
- SQLite 事务吞吐。
- 关键词和混合查询延迟。
- 查询 p50、p95 和 p99。
- 任务积压恢复速度。
- 索引重建时间和额外空间。
- daemon 空闲和负载内存。
- 数据、索引、日志和备份增长。

性能目标由需求迭代确定，测试应先建立可重复基线，不以牺牲持久性换取数字。

## 10. 记忆质量评估

评估集覆盖：

- 单事实。
- 用户偏好和约束。
- 当前状态和历史状态。
- 跨会话事实。
- 多跳关系。
- 冲突和修订。
- 过期、撤回和归档。
- 无答案和不相关查询。

指标：

```text
提取准确率
提取遗漏率
幻觉率
证据覆盖率
检索召回率
排序质量
跨空间污染率
时间判断准确率
冲突识别率
上下文信息密度
上下文 Token 成本
```

## 11. 回归要求

处理规则、模型、嵌入或排序权重变化前后，使用相同评估集对比：

- 质量变化。
- 延迟变化。
- Token 和资源变化。
- 新旧处理版本兼容性。
- 是否需要重建索引或重新处理原始事件。

质量下降或行为变化必须可归因到明确版本。
