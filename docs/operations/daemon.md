# dMeM Daemon 运行设计

## 1. 运行模型

dMeM 作为单个 Linux 用户拥有的常驻 Go 进程运行。一个数据目录同时只允许一个有效实例写入。

默认行为：

- 使用本地进程通信端点。
- 不监听网络地址。
- 数据、运行时文件和日志归当前用户所有。
- daemon 退出前停止接收新写入并完成可安全结束的事务。
- daemon 重启后恢复持久化任务。

## 2. 目录职责

逻辑目录：

```text
persistent/
  dmem.db

runtime/
  daemon endpoint
  pid or instance metadata

logs/
  operational logs
```

运行时目录、持久化目录、缓存目录和临时目录不得混用。清理缓存不能删除权威数据。

## 3. 单实例

启动时：

1. 验证数据目录所有权和权限。
2. 在 data dir 的 `daemon.lock` 上获取非阻塞 advisory file lock。
3. 检查现有端点是否属于有效实例。
4. 拒绝第二个使用同一数据目录的写实例。
5. 初始化 SQLite 和 schema。
6. 恢复任务并建立本地端点。

同一用户可以为不同 data dir 启动多个 daemon。锁是写实例的权威判断，socket 只用于服务发现。

## 4. 启动阶段

```text
配置加载
  → 目录和权限检查
  → 单实例检查
  → SQLite 打开和完整性检查
  → schema 版本兼容性检查
  → 派生索引状态检查
  → 中断任务恢复
  → 本地端点启用
  → readiness=true
```

启动失败必须保留可诊断错误，不得在数据库未准备好时返回就绪。

## 5. 关闭阶段

```text
收到关闭信号
  → readiness=false
  → 停止接收新任务
  → 允许进行中的短事务完成
  → 中止或持久化长任务状态
  → 关闭 worker
  → 关闭 SQLite
  → 删除本地运行时端点
  → 释放实例锁
```

关闭超时后可以强制退出，但任务必须能在下一次启动时识别为中断。

## 6. 服务端点

- 端点仅允许当前用户访问。
- 端点父目录不可被其他用户写入。
- 每个连接有请求大小、读取时间和执行时间限制。
- daemon 不把端点路径或 loopback 位置当作独立 Agent 身份。
- stale endpoint 必须安全清理，不能连接到错误实例。

runtime dir 模式 0700，socket 模式 0600。只有持有实例锁后才能清理 stale socket；若 socket 可连接且返回的 instance ID 或 data dir hash 不匹配，启动失败而不替换 socket。

未来网络模式必须单独定义认证、授权、加密、暴露范围和审计。

## 7. 资源治理

限制：

- 最大连接数。
- 最大请求和响应大小。
- 最大任务队列。
- worker 并发。
- SQLite 空间。
- 派生索引和缓存空间。
- 临时空间。
- 外部模型并发和调用预算。

磁盘低水位时：

1. 暂停统计和非关键索引任务。
2. 清理可重建缓存和过期临时文件。
3. 拒绝超限原始内容。
4. 保留只读查询能力。
5. 临界时进入受限写入或只读状态。

## 8. 维护模式

维护模式用于完整性检查、恢复和后续可能引入的升级操作：

- 拒绝普通写入。
- 允许健康检查和管理操作。
- 查询是否可用由维护操作决定。
- 客户端得到明确维护状态和重试建议。

## 9. 崩溃恢复

启动后检查：

- SQLite 完整性。
- 未提交事务由 SQLite 自身恢复。
- `running` 任务是否中断。
- 当前投影是否指向有效版本。
- 索引版本是否匹配权威版本。
- FTS 重建任务是否未完成。

权威数据错误和派生索引错误必须分开报告。派生错误优先重建，权威错误进入维护或只读状态。
